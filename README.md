# embeddedSOMEIP on STM32H7

STM32CubeIDE project that runs the [embeddedSOMEIP](Middlewares/Third_Party/EmbeddedSOMEIP) library on an STM32H743 and the benchmark test cases.

## Board

| | |
|---|---|
| Board | NUCLEO-H743ZI (Nucleo-144) |
| MCU | STM32H743ZIT6, Cortex-M7 at 400 MHz |
| Ethernet | on-board LAN8742 PHY over RMII |
| Addressing | DHCP, the board waits for a lease before starting |

Memory regions used by the image:

| Region | Used | Capacity | Holds |
|---|---|---|---|
| FLASH | 209K | 2048K | code and initializers |
| RAM_D1 | 453K | 512K | static pools of the SOME/IP library |
| RAM_D2 | 128K | 288K | FreeRTOS heap, plus the lwIP heap outside any section |

The D-cache is off. This keeps the CPU and the Ethernet DMA coherent without MPU carve-outs. The I-cache is on.

## Folders

| Folder | Contents |
|---|---|
| `Core/Inc`, `Core/Src` | application code, see the table below |
| `Core/Startup` | reset vector and startup assembly |
| `Drivers` | CMSIS, STM32H7 HAL, and the BSP with the LAN8742 PHY driver |
| `LWIP/App`, `LWIP/Target` | lwIP init and the port glue generated by CubeMX |
| `Middlewares/Third_Party/EmbeddedSOMEIP` | the SOME/IP library, a git submodule |
| `Middlewares/Third_Party/FreeRTOS`, `LwIP` | vendor middleware |
| `tools` | `footprint.py`, reports flash and RAM per module from the linker map |
| `Debug`, `Release` | build output |

Application files in `Core`:

| File | Purpose |
|---|---|
| `main.c` | clocks, MPU, peripheral init, starts one of the two apps |
| `someip_app.cpp` | the SOME/IP server, holds all test cases |
| `someip_app.h` | test case selection, see below |
| `udp_baseline_app.c` | plain UDP echo server, the latency baseline |
| `cpp_runtime.cpp` | routes C++ allocation to the FreeRTOS heap |
| `freertos.c` | places the FreeRTOS heap in D2 SRAM |

## Test cases

One scenario per flashed image. Pick it with `SOMEIP_TESTCASE` in the project's preprocessor defines, or with `-D`.

| Define | Board runs | Desktop client |
|---|---|---|
| `SOMEIP_TESTCASE=1` | request response server, no SD | `T1_rr_latency` |
| `SOMEIP_TESTCASE=2` | request response server offered via SD | `T2_sd_ttfm` |
| `SOMEIP_TESTCASE=3` | field and event group server, SD over UDP | `T3_notify_rr` and `T4_sd_ttfn` |
| `SOMEIP_TESTCASE=5` | SOME/IP-TP echo server, no SD | `T5_tp_rtt` |
| `UDP_BASELINE=1` | plain UDP echo, no SOME/IP | `B1_udp_rr` and `B3_udp_notify` |

`UDP_BASELINE=1` overrides the SOME/IP app and is the floor the T1 and T3 numbers are measured against.

`SOMEIP_TRANSPORT` picks UDP or TCP for cases 1 and 2 and must match the client's sweep. Case 3 is UDP because field events are UDP. Case 5 is UDP-TP.

Default is `SOMEIP_TESTCASE=2` over UDP.

## Build and flash

Open the project in STM32CubeIDE and build. Two configurations exist, `Debug` and `Release`. The benchmark numbers come from `Release`.

The library is compiled from source by this project, not by its own CMake. `SOMEIP_PLATFORM_STM32` is set here.

After cloning, fetch the library:

```console
git submodule update --init
```
